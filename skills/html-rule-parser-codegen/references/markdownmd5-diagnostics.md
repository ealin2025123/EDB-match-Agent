# `markdownMD5` 空结果诊断

当平台测试 JSON 中的 `ExcelData` 为空时，按照证据逐层归因。测试 JSON 和最终展示字段不是原始 Markdown 的替代品。

## 只读诊断顺序

1. 记录参数中的 `markdownMD5`、`fileMd5`、页面标题、当前脚本版本、当前输入键和返回键。
2. 通过既有下载接口只读下载 `markdownMD5`，检查原始 bytes 长度、解码结果、标题/核心指标关键词、段落和表格。再用同一参数调用 `main(params)`，记录返回码、消息、记录数量与四字段。
3. 仅为设计期对照，可只读检查 `fileMd5` 对应原网页是否含正文。生产代码绝不能把这一步变成运行时回退。
4. 在 Markdown 完整的前提下，才逐条检查 B 列正则的命中次数、匹配组数值、单位、方向词和日期来源；最后检查部署版本、缓存、路由、入参键和返回键。

## 归因矩阵

| 证据 | 结论 | 正确动作 |
|---|---|---|
| 实际 Markdown 有正文；本地 `main` 返回完整；平台仍空 | 部署、缓存、路由、返回键或下游筛选问题 | 核对运行的脚本版本、`markdownMD5` 映射、返回键和外部链路；不要改已验证正则 |
| 实际 Markdown 有正文；本地同样空；B 正则未命中或分组错误 | 解析器与实际 Markdown 不一致 | 在同一局部上下文修正正则、切分或噪声处理，并重新验证四字段 |
| Markdown 仅有导航字样、异常短，或没有任何本页核心指标；原网页有正文 | 上游 HTML→Markdown 丢失正文 | 返回明确失败状态/空结果，报告上游阻塞，待重新转换；不得读取 `fileMd5` 兜底 |
| 原网页和 Markdown 都没有目标指标 | 来源无有效数据或规则覆盖不符 | 不输出，记录证据；不要用历史数据补造 |

## 输入健康保护

对于指标正文型页面，解析器可在解析前检查转换 Markdown 是否异常短、是否只含典型导航文字、以及是否缺失所有已知核心指标关键词。命中时返回可见的失败消息而不是“成功 + 空结果”。

保护条件必须窄且基于已核对的页面语义：不能以“没匹配某一条正则”作为全局失败条件，也不能因此拒绝真实但仅含部分指标的后续页面。健康保护的作用是区分缺失输入与解析失败，不是替代正则或增加数据。

## HTML0901 对照经验

- 辽阳县：转换 Markdown 正文完整但存在排版空格；NFKC 与空白归一后，8 条 A/B 规则均能命中。应归因于转换噪声，解析器可做局部抗噪。
- 大洼区：原网页含 12 条目标指标，但测试 `markdownMD5` 仅含“打印/关闭”。这是上游数据丢失，不能因空结果改用原始 HTML 或降低 A/B 规则；应等待上游重新生成包含正文的 Markdown。
