# HTML 规则解析器生成

## 目标与边界

将非统一结构的 HTML 数据源处理为“每个来源一个独立 Python 解析器”。解析器设计期依据原始网页理解真实业务数据，运行期只能解析平台下载的 HTML 转 Markdown 内容。`main(params)` 是唯一对外入口；每条有效记录仅有 `indicator_name`、`indicator_data`、`indicator_unit`、`end_date`，且 `indicator_data` 为字符串。名称正则库只帮助定位真实数据，不能创造记录。

在开始前读取项目的 `AGENTS.md`、HTML 项目记忆、规则工作簿和既有代码契约。项目规则及用户明确要求优先于本 Skill。若任务要编辑 `.xlsx` 规则表，使用可用的电子表格技能并保持格式、工作表和未点名单元格不变。

## 处理顺序

1. 按实际表头读取用户指定的规则工作簿；本项目默认是 `excelrule/excelrule.xlsx`。记录采集来源、来源编码、路径代码、路径、目标表、G 列文件名称、备注、是否通过初步测试及四个待补字段。生成代码前先看“备注”和“是否通过初步测试”：若明确写有“无正则表”“无正则拼接内容”“无正则拼接规则”“MD5错误且文件错误”“文件错误且MD5错误”“文件错误且md5错误”等无法生成条件，直接跳过该行，不生成空规则或占位 `.py`。G 列显示标题时，读取单元格真实超链接；不要把标题当 URL 猜测。生成期判断原文身份、指标和统计期间，以 G 列实际网站页面为准；平台保存的 `fileMd5` 原文件可能错配，不得用它替代 G 列网站。即使备注要求“从源文件读取”或“用MD5读取”，也应先核对 G 列实际网站；网站不可访问或对应关系冲突时记录并请用户确认，不能自行用 MD5 件推断原文。
2. 名称正则库支持两种格式，按用户本轮指定的文件类型选择，不要混用：
   - 新正则表：优先用于当前批次，默认是 `excelname拼接规则/任务汇总总表0911.xlsx`。读取 Sheet `汇总`，按 C 列 `任务ID` 的**精确文本**匹配当前 `excelrule` 行的“数据源路径代码”；同一个任务ID可有多行，每一行等价于旧版同名 Sheet 中的一条指标正则。F 列是指标名称，K 列 `selectors` 中的 JSON 字符串包含正则逻辑，通常形如 `[{"selector_type":"regex","rules":["..."]}]`。生成期需解析 K 列，仅采用 `selector_type == "regex"` 的 `rules`；一个指标有多条 rules 时展开为多条候选正则。
   - 旧正则表：当用户指定 `指标名称正则逻辑_分路径代码*.xlsx` 这类按路径代码分 Sheet 的文件时，用路径代码的**精确文本**定位同名 Sheet。确认表头后，A 列是 `indicator_name`，B 列是定位该指标数值的正则。
   两种正则表都仅用于生成期，运行时不读取规则库。找不到任务ID、找不到旧 Sheet、或对应正则列无可用 regex rules 时记录“无可用正则”，不能以相近任务ID或相近 Sheet 替代。
3. 只读检查 G 列真实网页，确认文章标题、实际表格/正文、有效指标、数值、单位、增长方向、统计期间和无效内容。网页仅用于设计和核验，不能在生产解析器中再次访问。不要把 URL 路径中的发表年月、页面发布日期或平台 MD5 下载件误认成统计期间；网页标题与平台外部 `title` 冲突时明确报告。
4. 检查平台实际会传入的 Markdown。HTML 转换可能改变空白、破折号、段落、标点或表格，但不能假定它会保留全部网页正文。分别确定 Markdown 中的候选范围、表头/段落边界、日期和单位位置。若规则行 R 列有 `markdownMD5`，可用它下载 Markdown 做运行时兼容性回归，但不能用该 Markdown 改写 G 列网页的原文身份或统计期间；不得把具体 `markdownMD5` 写入任何运行时代码、模板、默认参数、兜底逻辑、测试入口或文件注释。若 R 列没有 `markdownMD5`，只按 G 列网页完成设计并标注“仅设计完成”，不以 `fileMd5` 原文件冒充网站核对。
5. 在规则表补齐并写具体：`指标单位取值逻辑`、`指标单位位置`、`截止日期取值逻辑`、`截止日期位置`。`end_date` 逐条候选数据按优先级解析：指标所在句子或表格单元格的统计期间；Markdown 页面标题的统计期间；外部通用 `params["title"]` 的统计期间。指标句子只有月份或季度、没有年份时，用页面标题、外部通用 `title` 或规则表截止日期逻辑中明确的统计年份补齐，仍以指标自身的月份或季度定期末。例如标题“2026年1-6月……”而指标自身是一季度累计值，取 `2026-03-31`；二季度累计值取 `2026-06-30`。“2025年1月—12月”取 `2025-12-31`，不能误取 1 月。“完成年度预算的36%”是预算进度，不是“全年”统计期间，也不是同比。指标句中出现多个期间时优先与该指标最近的明确统计期间；发布日期必须排除。不得收集全文日期后取最大值、最小值或排序结果。
   如果上述统计证据仍无法确定年份或日期，可将 `publictime` 作为最后兜底的**待确认候选**：已有“1-4月”等统计期间时，只借其年份，候选为该统计月末；统计期间也不存在时，单独列出拟采用的 `publictime` 日期。必须告知用户所用字段、推导过程和具体候选日期，取得确认后才写入解析器或规则表；不得静默使用发布日期、发文日期或 `pushtime`。说明截止日期逻辑时，始终给出如 `2026年4月30日` 的具体日期示例。规则正则与原文指向同一指标、仅金额单位不同时，可在解析器的匹配层兼容原文写法，但不得修改正则表中的指标名称和业务限定词；输出原文数值与原文单位（如 `亿元`），不在解析器换算成规则库单位（如 `万元`），由后续单位换算节点处理。正文“完成年度预算的49%”不能充作“累计同比”。源文没有明确单位时，名称含 `同比`、`增长` 或 `增速` 的比率指标可取 `%`；其他指标取 `"-"`，不得从相邻无关文本推断单位。
6. 再生成独立 Python 文件：保持项目 `main(params)` 接口和当前输出键；只将已核对的正则表规则、单位、日期和必要词表写入代码。新正则表写入 F/K 解析出的规则；旧正则表写入 A/B 规则。文件开头注释记录来源、路径代码、规则来源、网页核对、四字段取值位置及运行时 Markdown 边界；注释可记录用于核对的网页链接，但不得写具体 `markdownMD5` 或本机文件系统路径。本机路径如 `<local-workspace>`、临时脚本路径、工作区绝对路径只能出现在调试记录或交付说明中，不能进入生成的解析器文件。
7. 用同一 `markdownMD5` 或等价实际 Markdown 调用 `main(params)` 回归，检查严格 JSON、记录数、四字段、零值/负值/小数、无效值、层级、混合单位和多个期间。清理本次临时副本、缓存和 `.pyc` 后交付。

## 正则表、名称与字段规则

- 以 GZK 为最终名称依据的前提是指标含义相同。DeepSeek 应自主区分名称构造问题与明确不同的统计范围、币种、层级或期间。后者排除候选、记录不匹配依据并继续其他指标，不要求人工确认；例如“本外币各项贷款余额”及其同比不能匹配“外币各项贷款余额”及其同比。正则对子串的命中不证明语义相同，可加入上下文归属过滤，保持原始正则不变。只有证据不足、确实无法确定归属时才交人工处理。不同金额单位可后续换算，不据此排除。

- 新正则表 K 列 JSON selectors 中的 regex rules，或旧正则表 B 列正则，先在同一 Markdown 段落、句子或表格行中命中真实数值，才原样输出对应指标名称。新表输出 F 列名称；旧表输出 A 列名称。正则是主依据；名称存在不等于网页存在该指标。多次命中、数值无效或归属不唯一时不输出。
- 不直接修改规则工作簿中的 K 列或 B 列正则。代码中只可兼容已核对的 HTML→Markdown 转换噪声：NFKC 全半角归一、全角百分号、空白和换行压缩、千分位、中文/英文标点等价、段落/句子切分及原文已确认的段落归属过滤。兼容不得删除业务词、跨句拼接数值或扩展为未核对同义词。明确不同指标时按上述规则排除；不能靠改名改变业务含义。证据仍不足以判定时保留原文交人工处理。
- Markdown 与正则必须使用同一 Unicode 标准化。NFKC 可能把中文逗号、括号、冒号等转换为英文形式；若先标准化 Markdown，匹配前也要以同样方式标准化正则副本。保留工作簿正则原值，不把标准化结果写回工作簿。
- 正则转义必须区分 Python 源码、JSON 展示和实际运行字符串。源码 `r"\d+"` 与普通字符串 `"\\d+"` 等价，均用于匹配数字，不能仅见到源码或工具输出中的双反斜杠就判为重复转义。实际正则字符串若含两个连续反斜杠再接 `d`，例如源码 `r"\\d+"`，才会尝试匹配字面反斜杠及字母 d。对 `\s`、`\.`、`\(` 等同样检查。生成器从 JSON 读取规则时按结构调用 `json.loads()` 一次，从工作簿单元格读取时保留实际字符串；输出 Python 源码时只序列化一次，禁止对全部反斜杠盲目替换或用 `unicode_escape` 解码中文规则。
- 仅对数值书写噪声做局部清理：可删除数值及其紧邻单位内部的空白、英文/中文千分位分隔符，例如 `322 , 433 万 元` 归一为 `322433万元`。不得删除业务词、其他数值之间的分隔、或据此计算/补充数值。
- 候选范围优先使用同一 Markdown 表格行、句子或空行分隔的段落。若已核对的目标指标与其所属范围锚点位于同一段落但被句号切开，可保留该段落用于匹配；不得跨越空行分隔的段落，也不得因此把“州本级/市本级/县级”等相邻层级数据混入“全州/全市”目标。
- 当同一正则命中多处或跨入相邻业务段落时，先回看原始网页和实际 Markdown，判断数值是否属于同一指标。若能用原文中的明确标题、段落、表头或最近锚点限定归属，可在代码里加入归属过滤；若仍无法唯一归属，应向用户列出原文片段和建议，不要直接选择一个值。
- 只有当前匹配数值短语中明确出现“下降、减少、降低、少增、多减、减收、减支”等方向词时才将相应比率数值规范为负值。零值有效；不得默认去重、换算、四舍五入或补邻近值。
- 名称中的括号业务内容和单位必须保留。单位和日期逐条绑定同一指标及其统计期间；`publictime` 兜底未经用户确认时，候选日期只用于说明，不写入输出。

## 运行时契约与异常归因

当前 HTML 项目以运行时 Markdown MD5 下载 Markdown。接受 `markdownMD5`、`markdownMd5`、`markdown_md5`、`parseMarkdownMD5`、`parseMarkdownMd5`，并可把 JSON 字符串参数解析为对象；这些只是同一运行时入参的键名兼容，全部缺失时必须报缺参。下载结果按 `utf-8-sig`、`utf-8`、`gb18030`、`gbk` 等顺序解码；空结果、或开头疑似 `<!doctype html` / `<html` 的原始 HTML 必须报错。禁止回退读取 `fileMd5`、`parseFileMd5`、网页 URL、HTML DOM、R 列 `markdownMD5` 模板值或任何默认 MD5，也不得在代码或注释中写样例 MD5。当前 HTML0904 平台契约返回 `ExcelData`，不得返回 `OUTDATA` 或 `out_data`。HTML 运行时不读取或依赖 GZK/GZKJG/规则库，也不输出或伪造 `indicator_code`。为兼容平台扫描器，将 `def main(params)` 放在文件前部。

文件头注释推荐保留审计信息，格式可以类似：
```python
r"""
excelrule_row: 265
source_name: 河南省财政厅
path_code: 2085417117313806338
path: 河南省财政厅\信息公开\财政预决算\财政审计
source_url: https://czt.henan.gov.cn/2026/08-03/3381879.html
regex_sheet: 2085417117313806338
网页核对: 原始HTML和Markdown均包含“2026年5月预算执行简要分析”财政收支正文。
Markdown边界: 标题、发布时间、正文财政收支段至“相关阅读”；运行时仅解析markdownMD5下载内容。
单位位置: 财政金额数值后紧邻“亿元”；增长/下降/占比等变化率数值后的%。
日期位置: 标题/正文“5月份”“1-5月累计”，取统计期2026-05-31，不取发布时间。
说明: B列支出累计两条原始正则在核对Markdown中未命中；不修正规则、不伪造输出。
"""
```
生成文件中不得在代码或注释里写具体样例 MD5，也不要出现本机绝对路径、临时文件路径或工作区路径。

平台报“未找到 main 函数”时，先本地编译并动态加载确认目标 `.py` 是否暴露 `main(params)`，再检查上传/部署文件是否来自正确目录、是否复制时破坏缩进或转义、是否加载了旧同名文件。为兼容平台扫描器，建议把 `def main(params)` 放在文件前部，由它调用后面的实现函数。

生成模板中如果使用候选 span 去重逻辑或任何 `normalize_name(candidate_name)` 调用，必须同时生成：
```python
def normalize_name(value):
    return re.sub(r"\s+", "", unicodedata.normalize("NFKC", str(value or "")))
```
不得生成“调用了 `normalize_name()` 但没有定义”的文件；交付前必须静态扫描并编译确认。

测试结果为空时，不要立即修改正则。先检查入参键、返回键、部署版本和缓存，再读取该 `markdownMD5` 的实际 bytes 与解码文本，并以完全相同参数本地调用 `main(params)`。需要详细判断时，阅读 [MarkdownMD5 诊断参考](references/markdownmd5-diagnostics.md)。

怀疑重复转义时，先动态加载目标脚本并检查运行时规则字符串，再用实际 Markdown 中的数值、带小数点数字及括注分别验证对应规则。`repr()`、JSON 和工具输出本身也会转义反斜杠，必须区分展示层与实际字符。仅通过 `compile()` 或 `re.compile()` 不能证明规则语义正确。以同一 Markdown、同一参数记录修改前后的 `main(params)` 输出，确认缺失记录确实由该转义错误造成后再修复；已匹配的规则保持不变。若本地已能正常输出，只报告本地验证结果及平台差异，不直接断定部署版本错误，也不在未查看下游代码时断定空日期一定被过滤。

若网页正文完整而 `markdownMD5` 极短、只含导航文字或缺失所有核心指标，这是上游 HTML→Markdown 数据丢失：解析器不得绕过它去解析原始 HTML，也不得伪造数据。可返回清晰失败状态与空结果，记录为上游阻塞，等待重新转换后的 Markdown 再回归。

## 交付检查

- 规则行四个单位/日期字段已具体、可复核地填写；
- 路径代码精确对应本轮指定的正则表：新表按 C 列任务ID多行展开 F/K 规则；旧表按同名 Sheet 展开 A/B 规则；
- 网页设计期证据与实际 Markdown 证据均已区分记录；
- 代码只解析运行时 `params["markdownMD5"]` 下载的 Markdown，未硬编码示例数值、未运行时读取网页，且未使用 `fileMd5`、R 列 `markdownMD5`、模板值或任何默认 MD5 兜底；
- 每个输出项都有四字段，且可反查同一 Markdown 证据；
- 已用实际 Markdown 或等价夹具验证字典参数、JSON 字符串参数和缺失 `markdownMD5` 的报错；已检查数值字符串、负值、零值、单位和逐候选日期；
- 已核对运行时正则的反斜杠语义，并用真实数值/小数/括注验证涉及的规则；未将普通 Python 字符串或 JSON 展示中的合法转义误判为重复转义；
- 明确标注“网页与 Markdown 均验证”“仅设计完成”“无正则拼接规则”或“上游转换阻塞”，不混称。
