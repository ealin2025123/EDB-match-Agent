# 资产缓存与质量门禁

## 三层复用

HTTP 任务幂等避免客户端轮询或超时重试重复创建任务；已完成结果可按同一输入范围复用。解析资产缓存用于同一路径的新源文件，只复用代码或提示词，不把上一次的源数据作为本次结果。

路径统一分隔符及两侧空白，同路径归入一个组。版本由分支、规则、GZK、Skill 内容等范围决定；数组顺序变化不应使相同规则失效。源内容变化但资产写死日期等不适合复用时，保守地重新生成。

默认 HTTP 缓存索引位于 service-runtime/code-cache/，已审核资产位于 excel_match_agent/code/excel、code/html、code/prompt。命名使用完整路径分隔符转下划线，并处理 Windows 非法字符、保留设备名及过长文件名。人工改动、未知同名冲突不会自动覆盖。

缓存命中仍需对当前源文件预审、执行、匹配及审核；Prompt 仍需调用模型提取。缓存减少重复代码/提示词生成的 Token，而非消除全部模型调用。不宣称尚未测量的成本下降比例。

## 检查顺序

1. 有效 GZK 校验在下载及模型调用前执行，空规则立即返回。
2. 下载、读取真实源文件，再由配置的 DeepSeek 预审；明确无业务数据或完全不相关则停止，证据不足不武断否定。
3. 检查实际提取结果；有数据却提取为空可在原预算内重建，仍为空返回 EMPTY_EXTRACTION。
4. 统计期间按指标表头、实际源标题及文件名、本次 title 的顺序判断；publictime 仅是发布时间。仍为空返回 END_DATE_EMPTY。
5. 逐条源文证据与遗漏审核、GZK 语义匹配；至少两个不同编码且无待修复问题才通过。单位可换算不等于不同指标；不同统计范围或币种不能强配。
6. 首次加最多两次重建；缓存初次执行也占初轮。格式补问与业务重建分别记录，不以新任务绕过预算。

## 原始明细与匹配结果

ExcelData 是内部解析器返回字段；HTTP 的 excel_data 是最终通过轮次四字段投影：indicator_name、indicator_data、indicator_unit、end_date。HTML 从最终审核资产旁的 parsed-data.json 读取，Excel 从 ExcelData.json 读取，不从已经匹配或换算的 OUTDATA 倒推。

例：源值 48.82 亿元，excel_data 仍为 48.82 亿元；下游按 10000 换算后可得到 488200 万元。原始明细保留未匹配的真实记录，不能只复制 OUTDATA。

Prompt 当前业务结果只有 OUTDATA，不要求非空 excel_data。查询历史已成功的 Excel/HTML 任务时，服务可从保存的最终审核记录补充明细，不生成新代码，也不改写原任务历史。
