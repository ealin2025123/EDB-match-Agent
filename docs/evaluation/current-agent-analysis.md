# 当前 Agent 评测分析报告

评测日期 2026年11月6日。以现有Agent为准，未修改生产执行器、生成器、业务门禁或规则。DC实测按用户要求取消。

## 一 结论

本轮最明确的发现是评测入口存在输出包装适配错误。Prompt原生返回out_data，旧入口只读取ExcelData，导致已有正确候选被记为接口失败。统一包装后，用已保存的首次代码和模型响应重放，18个业务样本中10个候选与Gold等价，较原始首次试跑的5个增加5个。

这不是模型能力提升，也不是生产交付率从27.8%提升至55.6%；是纠正评测读取方式后恢复了5份候选的评分。没有重新调用模型，新增模型调用和Token均为0。

目前仍有7份代码不符合现有执行器约束，另有1份执行后为空。不能用这套结果宣称生产准确率为100%。

## 二 评测对象和标准

- 18个合成业务样本：Excel、HTML、Prompt各6个，每类覆盖相对简单、中等、复杂三个级别和两个期间，共36条目标记录。
- 6个异常场景：空GZK、无效文件、无业务数据、完全不相关、空提取、缺统计期间。
- 2个单位换算评分边界：正确换算接受，错误比例拒绝。
- 总计26个场景，不能说成26份真实地区资料。18个源主要是同一财政模板的变体，业务覆盖较窄。
- Gold逐一按源表/正文核对，记录为AI专家复核，没有人工签收。未公布的支出不计为漏提取。
- 数值、单位按明确比例做等价判断，例如41.82亿元等价于418200万元；指标身份与统计期间仍须正确。

## 五 失败归因与已处理事项

### 输出包装不一致

旧入口对Prompt响应直接读取ExcelData，与项目out_data约定冲突。修复仅位于评测适配层，允许识别已知的单一包装字段，保留数值、单位、日期及编码。多个包装同时出现、缺字段、非字符串字段或显式失败代码仍拒绝。

Prompt旧结果中部分记录没有indicator_code，因此这里评估的是提取候选，不把这些结果冒充生产完整契约通过。完整Prompt交付应另按当前Agent的五字段规范验证。

### 执行约束与旧生成资产不兼容

7份首次Python资产使用html模块，部分还使用HTMLParser初始化和类内私有字段，未通过当前worker的检查。已经撤回评测执行器中单独放宽这些限制的尝试。生产白名单和反射限制未改，相关样本仍记不兼容。

以后需要用当前Agent真实的生成契约重新生成这些资产，再单独评测。不能通过评测放宽规则或手改解析代码来提高通过率。

### 空提取与资产版本

一个Excel中等样本首次输出为空，原B/C试跑各经一轮重建恢复。说明限次反馈在该例有效，不等于总体修复成功率已得到可靠估计。

原D重放的是首次资产，包含已经被修复的旧代码，不能用4/18评价生产成功缓存。评测入口后续已改为优先使用本次审核通过的资产；该改动尚未完成新一轮真实模型闭环验证，不填入本次旧结果。
